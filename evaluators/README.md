# Evaluators

The final paper's primary metric is **complete-workload Execution correctness**. A candidate scores one only when the reference passes a nonempty developer workload and the candidate passes the same workload completely, exits successfully, and has no failed or cancelled tests. Partial test fractions and differential traces are diagnostics. The evaluator also reports Syntax correctness, CodeBLEU-R, ROUGE-L, and historical simplification/CodeBLEU components.

`config/eval.json` pins the evaluator schema and thresholds. `metrics/codebleu_recovery.py` implements the paper's four-component, recovery-aware CodeBLEU-R; `metrics/similarity.py` computes whole-module JavaScript-token ROUGE-L. Run with `PYTHONHASHSEED=0` to reproduce the archived data-flow normalization. Similarity requires a nonempty parser-accepted candidate, including validated JSX. The broader Syntax axis also requires Node acceptance and the statically resolvable export surface, so some Syntax-failing candidates still receive nonzero similarity.

```bash
ADB_CORPUS="$PWD/benchmark/realworld93" PYTHONHASHSEED=0 \
python3 evaluators/score.py \
  --manifest benchmark/realworld93/manifest.jsonl \
  --builds benchmark/realworld93/builds-jsob.jsonl \
  --predictions path/to/predictions.jsonl \
  --out path/to/scores.jsonl \
  --no-execution
```

Full execution additionally requires project-specific oracle sandboxes. The released final-paper per-output measurements are in `results/paper/ja93.jsonl`; older `results/runs/*/*/scores.jsonl` files were produced by an earlier scoring policy and remain for diagnostics. The reference-guided readability ratings are frozen in those paper records; they are not generated by `score.py`.

Run the focused evaluator tests with `python3 evaluators/tests/test_full_suite_score.py`, `python3 evaluators/tests/test_rouge_l.py`, and `PYTHONHASHSEED=0 python3 evaluators/tests/test_codebleu_recovery.py`. The broader metric fixture needs the materialized `corpus/subjects` tree, which is not included in this Git release.
